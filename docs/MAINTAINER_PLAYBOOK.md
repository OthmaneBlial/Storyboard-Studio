# Maintainer playbook

Storyboard Studio is maintained on a best-effort basis:

- triage new issues within 14 days when possible;
- publish a small release or a status update at least once per quarter;
- label proposals as renderer, accessibility, documentation, template,
  security, provider, or question;
- close declined or stale proposals with a reason and a pointer to the product
  contract, not a silent deletion;
- thank contributors in release notes and record the verification they ran.

For every merged external contribution, follow
[`CONTRIBUTOR_RECOGNITION.md`](CONTRIBUTOR_RECOGNITION.md): obtain attribution
consent, add a release-note credit tied to the pull request, and add a showcase
entry only when the contribution produced a public template, fixture, viewer
result, or user-facing artifact. Never automate star requests or imply an
endorsement.

Discussions are currently enabled. Keep them enabled only while a named
maintainer can review them at least weekly and answer or route them within the
same best-effort 14-day window as issues. If that capacity disappears, stop
promoting Discussions and disable new threads after preserving links to useful
answers. Issue forms and `SUPPORT.md` remain the canonical support path.
Pull requests retain the local-first, privacy, editability, and compatibility
checklist in `.github/PULL_REQUEST_TEMPLATE.md`.
